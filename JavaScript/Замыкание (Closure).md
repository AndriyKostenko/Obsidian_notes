

**Замыкание (Closure)** — это одна из самых важных и мощных концепций в JavaScript. Если говорить просто:

  

&gt; **Замыкание — это функция, которая «помнит» своё внешнее окружение, даже когда она выполняется вне этого окружения.**

  

Давай разберем это по шагам: от простого к сложному.

  

---

  

### 1. Сначала поймем «Лексическую область видимости»

В JavaScript функция имеет доступ к переменным, которые объявлены внутри неё, а также к переменным, объявленным снаружи (в родительской функции или в глобальной области). Это называется **лексической областью видимости**.

  

```javascript

let name = "Иван"; // Глобальная переменная

  

function sayHello() {

console.log("Привет, " + name); // Функция видит переменную 'name' извне

}

  

sayHello(); // Выведет: Привет, Иван

```

  

### 2. Что же такое замыкание?

Замыкание возникает, когда внутренняя функция «захватывает» переменные из внешней функции и продолжает иметь к ним доступ, даже после того, как внешняя функция уже завершила свою работу.

  

**Представь это как рюкзак:** Когда функция создается, она берет с собой «рюкзак» со всеми переменными, которые были ей доступны в момент рождения. Куда бы ты ни понес эту функцию, рюкзак всегда при ней.

  

#### Пример кода:

```javascript

function createCounter() {

let count = 0; // Эта переменная "спрятана" внутри функции

  

return function() {

// Эта анонимная функция — и есть замыкание

count++;

return count;

};

}

  

const counter = createCounter();

  

console.log(counter()); // 1

console.log(counter()); // 2

console.log(counter()); // 3

```

  

**Что здесь произошло?**

1. Мы вызвали `createCounter()`. Она создала переменную `count` и вернула нам новую функцию.

2. Работа `createCounter()` завершилась. Обычно переменные внутри функции должны удаляться из памяти.

3. Но функция, которую мы сохранили в переменную `counter`, **сохранила ссылку** на переменную `count`.

4. Каждый раз, когда мы вызываем `counter()`, она лезет в свой «рюккачок» (замыкание), находит там `count` и меняет его.

### 3. Зачем это нужно на практике?

  

#### А) Инкапсуляция (Приватные переменные)

В JavaScript долгое время не было приватных свойств в классах. Замыкания позволяют скрыть данные от прямого изменения извне.

  

```javascript

function bankAccount(initialBalance) {

let balance = initialBalance; // Никто не может изменить balance напрямую

  

return {

deposit: function(amount) {

balance += amount;

console.log("Баланс после депозита:", balance);

},

getBalance: function() {

return balance;

}

};

}

  

const myAcc = bankAccount(100);

myAcc.deposit(50); // Баланс после депозита: 150

console.log(myAcc.balance); // undefined (переменная недоступна снаружи!)

```

  

#### Б) Фабрики функций

Замыкания позволяют создавать функции с предустановленными параметрами.

  

```javascript

function makeMultiplier(multiplier) {

return function(number) {

return number * multiplier;

};

}

  

const double = makeMultiplier(2); // multiplier = 2 заперт внутри замыкания

const triple = makeMultiplier(3); // multiplier = 3 заперт внутри замыкания

  

console.log(double(5)); // 10

console.log(triple(5)); // 15

```

  

---

  

### Итог: три кита замыкания

  

1. **Вложенность:** У тебя есть функция внутри другой функции.

2. **Доступ к контексту:** Внутренняя функция использует переменную из внешней.

3. **Живучесть:** Внутренняя функция сохраняет доступ к этой переменной даже после того, как внешняя функция перестала выполняться.

  

**Важное замечание (про память):**

Так как замыкание удерживает переменные «живыми», они не удаляются сборщиком мусора. Если создавать тысячи замыканий и хранить их в глобальных переменных, это может привести к избыточному потреблению оперативной памяти (утечкам памяти). Но в обычном коде это используется повсеместно и безопасно.
