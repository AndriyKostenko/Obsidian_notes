
В современном Go (и в целом в идиоматичном) подход к созданию переменных строится вокруг философии **минимума бойлерплейта** и **максимального вывода типов (type inference)**. 

Синтаксис Go в этом плане не менялся радикально с момента выхода, но «современный» стиль диктует четкие правила: когда использовать короткий оператор, а когда явное объявление.

Вот как это выглядит сегодня:

### 1. Короткое объявление `:=` (Стандарт для локальных переменных)
Это самый частый способ создания переменных внутри функций. Компилятор сам определяет тип на основе присвоенного значения.

```go
// Вместо var name string = "Golang"
name := "Golang" 

// Вместо var count int = 0
count := 42 

// Инициализация структур (Composite Literals)
user := User{
    ID:   1,
    Name: "Alice",
}

// Срезы и карты
items := []string{"a", "b"}
cache := make(map[string]int) // или cache := map[string]int{}
```
**Правило:** Если вы объявляете переменную внутри функции и сразу присваиваете ей значение — **всегда используйте `:=`**.

---

### 2. Явное объявление через `var`
Ключевое слово `var` в современном коде используется только в трех случаях:

**А. Глобальные переменные (на уровне пакета)**
Короткий оператор `:=` не работает вне функций.
```go
package main

var ServerVersion = "1.0.0" // Тип выведется (string)
var MaxConnections int      // Явное указание типа для нулевого значения (0)
```

**Б. Когда нужно объявить переменную, но инициализировать позже**
Если вы не знаете значение на момент объявления, но вам нужно «зарезервировать» переменную (она получит *zero value*).
```go
var result []byte
// ... много кода ...
result, err := doSomething() // Ошибка! Нельзя использовать :=, если result уже объявлена через var, а err новая. 
// Правильно:
var err error
result, err = doSomething() 
```

**В. Когда нужен тип, отличающийся от типа по умолчанию**
Например, вам нужен `int8`, а не `int`, или вы приводите к интерфейсу.
```go
var smallNum int8 = 10       // Без var компилятор сделал бы просто int
var reader io.Reader = os.Stdin 
```

---

### 3. Группировка `var ( ... )`
Используется для красивого форматирования, когда нужно объявить много переменных сразу (чаще на уровне пакета, но иногда и в функциях).

```go
var (
    home   = os.Getenv("HOME")
    user   = os.Getenv("USER")
    gopath = os.Getenv("GOPATH")
)
```

---

### 4. Неизменяемые переменные (`const`)
В Go нет ключевого слова `let` (как в Swift/Rust/JS), чтобы сделать обычную переменную неизменяемой. Но для констант используется `const`. 

**Современный паттерн для «Enum» через `iota`:**
```go
const (
    StatusPending = iota // 0
    StatusActive         // 1
    StatusClosed         // 2
)
```

### 🔥 Современные нюансы (Go 1.22+)

Если вы пишете на современном Go, вы должны знать об одном важном изменении, касающемся переменных:

**Проблема переменных в циклах (исправлена в Go 1.22)**
До Go 1.22 переменная цикла `for` была *одной на всех*, из-за чего при запуске горутин внутри цикла возникали баги (шейдодинг/захват одной и той же памяти). Разработчикам приходилось писать «костыль»:
```go
// СТАРЫЙ КОД (до Go 1.22)
for i, v := range values {
    i := i // Копирование переменной, чтобы горутина захватила уникальное значение
    v := v 
    go func() {
        fmt.Println(i, v)
    }()
}
```
**В современном Go (1.22 и новее)** переменные цикла создаются заново для каждой итерации. Этот костыль больше **не нужен** и считается устаревшим (bad smell):
```go
// СОВРЕМЕННЫЙ КОД (Go 1.22+)
for i, v := range values {
    go func() {
        fmt.Println(i, v) // Всё работает безопасно
    }()
}
```

### ⚠️ Главная опасность `:=` (Shadowing / Затенение)
Оператор `:=` может случайно создать **новую** переменную во вложенной области видимости, если вы ошибетесь в имени или объявите новую переменную слева от `:=` вместе с нужной.

```go
user := "Alice"

if condition {
    // ОШИБКА: создается НОВАЯ локальная переменная user, 
    // внешняя остается "Alice"
    user, err := fetchUser() 
}
// Здесь user всё еще "Alice"
```
**Современный совет:** В IDE (GoLand, VS Code) всегда включайте линтеры (например, `govet` или `golangci-lint`), они подсвечивают случайное затенение переменных (shadowing).

### Резюме (Rule of Thumb)
1. Локальная переменная + есть значение сразу? ➡️ `:=`
2. Глобальная переменная? ➡️ `var`
3. Нужен нулевой тип (zero-value) для последующего присваивания? ➡️ `var`
4. Нужен специфичный тип (не дефолтный)? ➡️ `var name Type = ...`
5. Значение никогда не меняется? ➡️ `const`
