1. Единый механизм: "Копирование ссылки"

Когда ты передаешь аргумент в функцию, Python **не копирует сам объект** (не делает глубокой копии) и **не передает переменную как ссылку в стиле C++**.

Вместо этого он **копирует ссылку (указатель) на объект** в локальную переменную функции.

Представь, что объект — это **коробка с данными**, а переменная — это **бирка на коробке**.
*   Когда ты вызываешь функцию, ты создаешь **новую бирку** с тем же именем (аргумента), которая вешается на **ту же самую коробку**.

### 2. Почему поведение различается?

Разница в поведении возникает не из-за способа передачи, а из-за того, **можно ли изменить содержимое коробки**.

#### Случай А: Неизменяемые типы (int, str, tuple)
Ты не можешь изменить объект `int` внутри коробки. Если ты пишешь `x = x + 1`, Python создает **новую коробку** (новый объект числа) и вешает локальную бирку `x` на неё. Внешняя бирка остается на старой коробке.

```python
def change_val(x):
    x = 100  # Создаем новый объект 100 и вешаем локальную бирку 'x' на него

a = 5
change_val(a)
print(a)  # Вывод: 5 (внешняя бирка все еще на объекте 5)
```
**Иллюзия:** Кажется, что передавалось "по значению" (копия), потому что внешняя переменная не изменилась.

#### Случай Б: Изменяемые типы (list, dict, set)
Ты можешь изменить содержимое коробки, не создавая новую. Методы вроде `.append()` меняют объект "на месте" (in-place). Так как бирки внутри и снаружи указывают на одну коробку, изменения видны везде.

```python
def change_list(lst):
    lst.append(100)  # Меняем содержимое той же самой коробки

my_list = [1, 2]
change_list(my_list)
print(my_list)  # Вывод: [1, 2, 100] (изменения видны снаружи)
```
**Иллюзия:** Кажется, что передавалось "по ссылке", потому что внешняя переменная изменилась.

#### Случай В: Ловушка с изменяемыми типами
Если внутри функции ты попытаешься **переприсвоить** изменяемую переменную, магия исчезнет. Ты просто повесишь локальную бирку на новую коробку, как в случае с числами.

```python
def replace_list(lst):
    lst = [99, 99]  # Создаем НОВЫЙ список и вешаем локальную бирку 'lst' на него

my_list = [1, 2]
replace_list(my_list)
print(my_list)  # Вывод: [1, 2] (внешний список не изменился!)
```
Это доказывает, что механизм передачи одинаковый: в обоих случаях (и с `int`, и с `list`) переприсваивание локального аргумента не влияет на внешнюю переменную.

### 3. Как это выглядит внутри CPython?

Возвращаясь к внутреннему устройству, о котором мы говорили раньше:

В CPython каждая переменная — это структура `PyObject*` (указатель на объект).
Когда вызывается функция:
1.  Создается новый фрейм (стек вызова).
2.  В локальные переменные фрейма записываются **копии указателей** на объекты.

```c
// Упрощенно, что происходит в C
void python_function(PyObject* arg) { 
    // arg - это копия указателя, переданного при вызове
    // Сам объект по этому адресу не копируется
}
```

*   Для `int`: `arg` указывает на объект числа. Если сделать `arg = PyLong_FromLong(100)`, мы просто меняем локальный указатель `arg`.
*   Для `list`: `arg` указывает на объект списка. Если сделать `PyList_Append(arg, ...)`, мы идем по указателю и меняем память самого объекта списка.

### 4. Резюме

| Утверждение | Верно? | Пояснение |
| :--- | :--- | :--- |
| Неизменяемые передаются по значению | ❌ Нет | Передается ссылка, но объект нельзя изменить, поэтому создается новый. |
| Изменяемые передаются по ссылке | ❌ Нет (технически) | Передается ссылка, но это не "ссылка на переменную" (как в C++), а "ссылка на объект". |
| **Всё передается как ссылка на объект** | ✅ **Да** | Копируется указатель на объект. |

**Правило большого пальца:**
*   Если ты **изменяешь объект** (методы `.append`, `.update`, изменение атрибутов) — изменения видны снаружи.
*   Если ты **переприсваиваешь имя** (`x = ...`) — изменения видны только внутри функции.
