[[Async in Python]]

### 1. Главное препятствие: GIL (Global Interpreter Lock)

Прежде чем выбирать инструмент, нужно понять **GIL**.
В стандартном интерпретаторе Python (CPython) существует глобальная блокировка, которая разрешает **только одному потоку** выполнять байт-код Python в один момент времени.

*   **Что это значит?** Даже если у вас 8 ядер процессора и 8 потоков, код Python будет выполняться последовательно на одном ядре (с быстрым переключением).
*   **Исключение:** GIL отпускается во время операций ввода-вывода (I/O) и при вызове некоторых C-библиотек (например, NumPy).

Это диктует правило выбора:
*   **Потоки (Threading):** Для задач, связанных с ожиданием (I/O-bound).
*   **Процессы (Multiprocessing):** Для задач, связанных с вычислениями (CPU-bound).

---

### 2. Потоки (`threading`)

Потоки легковесны, работают в одном процессе и имеют **общую память**.

**Когда применять:**
*   Сетевые запросы (API, scraping).
*   Работа с файлами/диском.
*   Ожидание ответов от баз данных.
*   GUI приложения (чтобы интерфейс не зависал).

**Как применять:**
Можно использовать низкоуровневый модуль `threading` или высокоуровневый `concurrent.futures`.

```python
import threading
import time

def worker(n):
    print(f"Поток {n} начал работу")
    time.sleep(2)  # Имитация I/O операции
    print(f"Поток {n} закончил работу")

threads = []
for i in range(5):
    t = threading.Thread(target=worker, args=(i,))
    t.start()
    threads.append(t)

for t in threads:
    t.join()
```

**Лучшая практика:** Используйте `concurrent.futures.ThreadPoolExecutor`. Это проще и безопаснее.

```python
from concurrent.futures import ThreadPoolExecutor

def fetch_url(url):
    # ... запрос к сети ...
    return "data"

with ThreadPoolExecutor(max_workers=10) as executor:
    results = executor.map(fetch_url, list_of_urls)
```

### 3. Процессы (`multiprocessing`)

Процессы тяжелее, у каждого **своя память** и **свой интерпретатор Python** (а значит, свой GIL). Это позволяет задействовать все ядра процессора.

**Когда применять:**
*   Сложные математические вычисления.
*   Обработка изображений/видео.
*   Парсинг больших данных с тяжелой обработкой.
*   Задачи, требующие 100% загрузки CPU.

**Как применять:**
Модуль `multiprocessing` или `ProcessPoolExecutor`.
⚠️ **Важно:** На Windows код запуска процессов должен быть внутри `if __name__ == '__main__':`.

```python
from multiprocessing import Process
import os

def heavy_calc(n):
    print(f"Процесс {os.getpid()} считает {n}")
    sum = 0
    for i in range(10_000_000):
        sum += i
    return sum

if __name__ == '__main__':
    processes = []
    for i in range(4):
        p = Process(target=heavy_calc, args=(i,))
        p.start()
        processes.append(p)

    for p in processes:
        p.join()
```

**Лучшая практика:** `concurrent.futures.ProcessPoolExecutor`.

```python
from concurrent.futures import ProcessPoolExecutor

if __name__ == '__main__':
    with ProcessPoolExecutor(max_workers=4) as executor:
        results = executor.map(heavy_calc, range(4))
```

### 4. Примитивы блокировок и синхронизации

Поскольку потоки делят память, а процессы — нет (но могут обмениваться данными), нужны механизмы для координации, чтобы избежать **состояний гонки (Race Conditions)** и **взаимных блокировок (Deadlocks)**.

Все эти классы находятся в модулях `threading` (для потоков) и `multiprocessing` (для процессов). Интерфейс у них почти одинаковый.

#### 1. Lock (Мьютекс)
Базовая блокировка. Только один поток может владеть блокировкой.
```python
import threading

lock = threading.Lock()
counter = 0

def increment():
    global counter
    with lock:  # Гарантирует атомарность
        counter += 1
```

#### 2. RLock (Reentrant Lock)
Позволяет одному и тому же потоку захватывать блокировку несколько раз (полезно при рекурсии или когда метод класса вызывает другой метод того же класса, требующий блокировки).
```python
rlock = threading.RLock()
# Поток может вызвать rlock.acquire() дважды, но должен дважды вызвать release()
```

#### 3. Semaphore (Семафор)
Позволяет ограниченному количеству потоков получить доступ к ресурсу одновременно.
*Пример:* Ограничить количество одновременных подключений к базе данных до 5.
```python
sem = threading.Semaphore(5)

def access_resource():
    with sem:
        # Делать работу, не более 5 потоков одновременно
        pass
```

#### 4. Event (Событие)
Флаг для сигнализации между потоками. Один поток ждет, другой устанавливает флаг.
*Пример:* Поток-загрузчик ждет, пока поток-инициализатор подготовит конфигурацию.
```python
event = threading.Event()

def waiter():
    print("Жду сигнала...")
    event.wait()  # Блокируется здесь
    print("Сигнал получен!")

def signaler():
    time.sleep(2)
    event.set()  # Разблокирует waiter
```

#### 5. Condition (Условие)
Более сложная конструкция, чем Event. Позволяет потокам ждать выполнения определенного условия, связанного с состоянием данных. Часто используется в паттерне "Производитель-Потребитель".
```python
cond = threading.Condition()
data_ready = False

def consumer():
    with cond:
        while not data_ready:
            cond.wait()  # Ждет уведомления
        # Обработать данные

def producer():
    with cond:
        # Подготовить данные
        data_ready = True
        cond.notify()  # Уведомить одного ждущего
        # или cond.notify_all()
```

#### 6. Queue (Очередь) — Самый рекомендуемый способ
Вместо того чтобы делить переменные и ставить на них замки, лучше передавать данные через потокобезопасную очередь. Это устраняет большинство проблем с синхронизацией.
*   `queue.Queue` — для потоков (`threading`).
*   `multiprocessing.Queue` — для процессов.

```python
import queue
import threading

q = queue.Queue()

def producer():
    for i in range(5):
        q.put(i)
    q.put(None) # Сигнал конца

def consumer():
    while True:
        item = q.get()
        if item is None:
            break
        print(f"Обработано: {item}")
        q.task_done()
```

### 5. Сводная таблица выбора

| Характеристика | Потоки (`threading`) | Процессы (`multiprocessing`) | Асинхронность (`asyncio`) |
| :--- | :--- | :--- | :--- |
| **Память** | Общая (легкий обмен) | Раздельная (нужна сериализация) | Общая (в рамках процесса) |
| **GIL** | Влияет (нет параллелизма CPU) | Не влияет (настоящий параллелизм) | Влияет (однопоточный цикл) |
| **Нагрузка** | Низкая (легче создать) | Высокая (тяжелее создать) | Очень низкая |
| **Лучше для** | **I/O-bound** (сеть, диск) | **CPU-bound** (вычисления) | **I/O-bound** (много соединений) |
| **Сложность** | Средняя (риск гонок) | Средняя (сложнее отладка) | Высокая (нужен async/await везде) |

### 6. Частые ошибки и советы

1.  **Deadlock (Взаимная блокировка):** Случается, когда два потока ждут блокировки друг друга.
    *   *Совет:* Всегда захватывайте блокировки в одном и том же порядке. Используйте `with lock`, чтобы не забыть `release`.
2.  **Race Condition (Гонка данных):** Результат зависит от порядка выполнения потоков.
    *   *Совет:* Используйте `Queue` вместо общих переменных. Если переменная общая — защищайте `Lock`.
3.  **Daemon Threads:** Потоки-демоны умирают сразу, как только завершается главная программа.
    *   *Совет:* Осторожно с `daemon=True`, данные могут не успеть сохраниться.
4.  **Сериализация в процессах:** При передаче данных между процессами они сериализуются (pickle).
    *   *Совет:* Не передавайте лямбда-функции или сложные объекты, которые нельзя сериализовать, в аргументы процессов.
5.  **Альтернатива:** Для высоконагруженного I/O (тысячи соединений) рассмотрите `asyncio` вместо потоков. Это часто эффективнее.

### Итог

1.  Нужно грузить процессор? → **`multiprocessing`** (`ProcessPoolExecutor`).
2.  Нужно ждать сеть/диск? → **`threading`** (`ThreadPoolExecutor`) или **`asyncio`**.
3.  Нужно передавать данные между задачами? → Используйте **`Queue`**.
4.  Нужно защитить общую переменную? → Используйте **`Lock`**.
