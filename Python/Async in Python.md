## 🔹 Что такое асинхронность?

Асинхронность — это способ выполнения операций, при котором программа **не блокируется**, ожидая завершения долгой операции (например, запроса к сети или чтения файла). Вместо этого она может **переключаться** между разными задачами, пока одни "ждут".

Это особенно полезно для:
- Веб-запросов
- Работы с сетью
- Операций ввода-вывода (I/O)
- Веб-серверов

---

## 🔹 Основные понятия

В Python асинхронность реализована через:
- `async def` — определение асинхронной функции
- `await` — ожидание результата асинхронной операции
- `asyncio` — встроенная библиотека для работы с асинхронностью
- `asyncio.run()` — запуск асинхронной программы

---

## 🔹 Пример 1: Простая асинхронная функция

```python
import asyncio

async def say_hello():
    print("Привет...")
    await asyncio.sleep(1)  # Имитация задержки (например, запрос к API)
    print("...мир!")

# Запуск асинхронной функции
asyncio.run(say_hello())
```

**Вывод:**
```
Привет...
(пауза 1 секунда)
...мир!
```

> `await asyncio.sleep(1)` — это **неблокирующая** пауза. Пока она работает, Python может делать что-то другое.

---

## 🔹 Пример 2: Запуск нескольких задач параллельно

```python
import asyncio

async def task(name, delay):
    print(f"Задача {name} началась")
    await asyncio.sleep(delay)
    print(f"Задача {name} завершена")

async def main():
    # Запускаем задачи конкурентно
    await asyncio.gather(
        task("A", 2),
        task("B", 1),
        task("C", 3)
    )

asyncio.run(main())
```

**Вывод:**
```
Задача A началась
Задача B началась
Задача C началась
Задача B завершена
Задача A завершена
Задача C завершена
```

> `asyncio.gather()` позволяет запускать несколько задач **одновременно**. Общее время выполнения ≈ 3 секунды (а не 2+1+3=6!).

## 🔹 Пример 3: Асинхронный веб-запрос (с библиотекой `aiohttp`)

Установим `aiohttp`:
```bash
pip install aiohttp
```

Теперь пример:

```python
import asyncio
import aiohttp

async def fetch_url(session, url):
    async with session.get(url) as response:
        print(f"Получено: {response.status} от {url}")
        return await response.text()

async def main():
    urls = [
        "https://httpbin.org/delay/1",
        "https://httpbin.org/delay/2",
        "https://httpbin.org/json"
    ]

    async with aiohttp.ClientSession() as session:
        tasks = [fetch_url(session, url) for url in urls]
        results = await asyncio.gather(*tasks)
        print(f"Получено {len(results)} ответов")

asyncio.run(main())
```

> Все запросы выполняются **одновременно**, а не один за другим. Это сильно ускоряет работу.

## 🔹 Как это работает "под капотом"?

Асинхронность в Python работает на основе **event loop** (цикл событий):

1. Запускается `asyncio.run(main())`
2. Создаётся **event loop**
3. Когда встречается `await`, Python говорит: "я могу подождать, перейду к другой задаче"
4. Как только операция (например, сеть) завершается — задача возобновляется

👉 Это **не многопоточность**, а **сопрограммы (coroutines)**, которые управляются одним потоком, но эффективно переключаются.

---

## 🔹 Когда использовать асинхронность?

✅ Подходит:
- Много I/O операций (сеть, файлы, базы данных)
- Веб-серверы (FastAPI, Quart)
- Парсинг сайтов
- Чат-боты

❌ Не подходит:
- CPU-тяжёлые задачи (расчёты, обработка изображений)
- Там лучше использовать `multiprocessing`

## 🔹 Полезные функции из `asyncio`

| Функция | Описание |
|--------|--------|
| `await asyncio.sleep(n)` | Неблокирующая задержка |
| `asyncio.gather(*tasks)` | Запуск нескольких задач |
| `asyncio.create_task(coro)` | Запуск задачи в фоне |
| `asyncio.as_completed(tasks)` | Итерация по задачам по мере завершения |

---

## 🔹 Пример с `create_task`

```python
async def main():
    task1 = asyncio.create_task(task("A", 2))
    task2 = asyncio.create_task(task("B", 1))

    await task1
    await task2

asyncio.run(main())
```

> `create_task` запускает задачу сразу, не блокируя выполнение.

### 🔹 Краткий ответ:

Когда Python встречает `await some_func()`, он:
1. **Выполняет** `some_func()` (если это сопрограмма — `coroutine`),
2. Но **приостанавливает текущую функцию**, пока `some_func()` **не завершится**,
3. При этом **не блокирует весь поток** — event loop может переключиться на другие задачи, **если `some_func()` "уходит в ожидание"** (например, сеть, задержка и т.п.).

---

### 🔹 Подробнее: как работает `await`

Представим, что у нас есть:

```python
async def slow_operation():
    await asyncio.sleep(2)
    return "Готово!"

async def main():
    print("Начинаю...")
    result = await slow_operation()  # ← вот здесь await
    print(result)
```

#### Что происходит по шагам:

1. `main()` начинает выполняться.
2. Встречается `await slow_operation()`.
3. Python **вызывает** `slow_operation()` и получает **объект-сопрограмму** (coroutine).
4. Затем `await` говорит:  
   > "Я хочу получить результат этой сопрограммы, но если она ещё не готова — я могу подождать, а пока **event loop пусть займётся чем-то другим**".
5. Внутри `slow_operation()` встречается `await asyncio.sleep(2)` — это **точка ожидания**.
   - `sleep(2)` — это **не блокирующая** задержка.
   - Event loop **запоминает**, что эта задача должна возобновиться через 2 секунды.
   - И **переключается** на другие задачи (если они есть).
6. Через 2 секунды event loop возвращается к этой задаче, продолжает выполнение.
7. `slow_operation()` возвращает `"Готово!"`.
8. `main()` получает результат и продолжается.

---

### 🔹 Важно: `await` ≠ откладывание вызова

> ❌ **Нет**, `await some_func()` **не откладывает вызов** `some_func()`.

✅ Наоборот — `some_func()` **выполняется сразу**, и `await` **ждёт её завершения**, но **неблокирующе**, если внутри есть точки ожидания (`await`).

---

### 🔹 Пример: что будет, если нет `await` внутри?

```python
async def quick_task():
    print("Быстрая задача началась")
    # Нет await — не даёт возможности переключиться
    for i in range(100_000_000):
        pass  # тяжёлый цикл
    print("Быстрая задача завершена")
    return "OK"

async def main():
    await quick_task()  # ❗️Здесь await, но внутри нет ожидания
```

> ❗️Несмотря на `await`, **event loop не сможет переключиться** на другие задачи, потому что `quick_task()` **занимает процессор** и не содержит `await`. Это **блокирует** event loop!

👉 Такие задачи нужно выполнять в **отдельном потоке/процессе** через `run_in_executor`.

---

### 🔹 А что, если хочется "отложить" выполнение?

Тогда нужно **явно создать задачу**, чтобы она выполнялась параллельно:

```python
async def main():
    task = asyncio.create_task(slow_operation())  # ← запустили в фоне
    print("Пока ждём, делаем что-то полезное...")
    result = await task  # ← теперь ждём результат
    print(result)
```

> Здесь `slow_operation()` **начинает выполняться сразу**, но `main()` не блокируется — можно делать другие дела.

---

### 🔹 Резюме

| Ситуация | Что делает `await some_func()` |
|--------|-------------------------------|
| `some_func()` — асинхронная, содержит `await` | Выполняет `some_func()`, приостанавливает текущую функцию, **event loop может переключиться** на другие задачи |
| `some_func()` — асинхронная, но без `await` внутри | Выполняется "синхронно", **блокирует event loop**, пока не закончится |
| `some_func()` — не вызвана с `await` | Получим **объект-сопрограмму**, но она **не запустится** (и будет предупреждение) |

---

### 🔹 Правило большого пальца

> `await` — это **точка, где можно переключиться на другие задачи**, **только если** внутри ожидаемой сопрограммы есть реальные асинхронные операции (`sleep`, сетевые запросы и т.п.).

## 🎬 Визуальная схема: Как работает `asyncio` с `await`

Представим, что у нас есть 3 задачи:

```python
async def task_A():
    print("A1")
    await asyncio.sleep(2)  # ждём 2 сек
    print("A2")

async def task_B():
    print("B1")
    await asyncio.sleep(1)  # ждём 1 сек
    print("B2")

async def task_C():
    print("C1")
    await asyncio.sleep(3)
    print("C2")

async def main():
    await asyncio.gather(task_A(), task_B(), task_C())
```

Теперь посмотрим, как event loop **переключается** между ними.

---

### ⏱️ Шаг 1: Запуск всех задач

```
Event Loop
│
├── Запускает task_A() → печатает "A1"
├── Запускает task_B() → печатает "B1"
├── Запускает task_C() → печатает "C1"
│
▼
Теперь все задачи дошли до `await asyncio.sleep(...)`
```

**Вывод на этом этапе:**
```
A1
B1
C1
```

> Все задачи **одновременно** дошли до `await` и "успят". Event loop **не блокируется**, он помнит:
- Возобновить A через 2 сек
- Возобновить B через 1 сек
- Возобновить C через 3 сек

---

### ⏱️ Шаг 2: Через 1 секунду — просыпается task_B

```
          task_A: ⏳ осталось 1 сек
          task_B: ✅ проснулся! → печатает "B2"
          task_C: ⏳ осталось 2 сек

Event Loop:
  Переключается на task_B → выполняет оставшуюся часть
```

**Вывод:**
```
B2
```

---

### ⏱️ Шаг 3: Через 2 секунды — просыпается task_A

```
          task_A: ✅ проснулся! → печатает "A2"
          task_B: ✅ завершён
          task_C: ⏳ осталось 1 сек
```

**Вывод:**
```
A2
```

---

### ⏱️ Шаг 4: Через 3 секунды — просыпается task_C

```
          task_C: ✅ проснулся! → печатает "C2"
          Все задачи завершены
```

**Вывод:**
```
C2
```

---

### 🔚 Итоговый вывод:

```
A1
B1
C1
B2
A2
C2
```

> ❗️ Обрати внимание: задачи **не выполняются одна за другой**, а **работают конкурентно** в одном потоке.

---

### 🧠 Как это выглядит в "памяти" event loop

```
Event Loop (цикл событий)
│
├── Задача A: await sleep(2) → запланировано: возобновить в 00:00:02
├── Задача B: await sleep(1) → запланировано: возобновить в 00:00:01
├── Задача C: await sleep(3) → запланировано: возобновить в 00:00:03
│
▼
Прошло 1 сек:  →  B готов → выполняется
Прошло 2 сек:  →  A готов → выполняется
Прошло 3 сек:  →  C готов → выполняется
```

---

### 🔄 Переключение контекста (context switch)

```
Основной поток:
  | task_B | task_A | task_C |
  ▼        ▼        ▼
  B1       A1       C1
           (все пошли в await)
  ----------------------------> время
           B2 (1s)  A2 (2s)     C2 (3s)
```

> Event loop **не тратит время впустую**, пока задачи "спят".

---

## 💡 Почему это не многопоточность?

- Все задачи выполняются **в одном потоке**.
- Переключение между ними — **кооперативное**: только в точках `await`.
- Нет накладных расходов на управление потоками.
- Нет проблем с гонками (race conditions), если не использовать общие ресурсы.

---

## 🧩 Когда переключение **не происходит**?

```python
async def bad_task():
    print("Начало")
    for i in range(1_000_000_000):  # долгий цикл
        pass
    print("Конец")
```

> ❌ Здесь **нет `await`**, значит, event loop **не может переключиться**. Вся программа **зависнет** на 10 секунд, даже если есть другие задачи.

👉 Такие операции нужно выносить в отдельный поток:

```python
await asyncio.to_thread(bad_task)  # выполнить в фоновом потоке
```

---

## ✅ Вывод

Асинхронность в Python — это **кооперативная многозадачность** в одном потоке:

- `await` — это **точка, где можно передать управление** другим задачам.
- `asyncio` использует **event loop**, который управляет задачами.
- Идеально подходит для **I/O-операций**, но не для CPU-нагрузки.
