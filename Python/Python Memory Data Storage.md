В Python модель проще и одновременно сложнее: **всё является объектом, и почти всё хранится в куче (Heap).**

Давай разберем по полочкам: переменные, функции, классы и то, как этим управляет память.

---

### 1. Главное правило: Всё в Куче (Heap)

В CPython **нет понятия «переменная хранит значение»**.
*   **Значения (объекты):** Числа, строки, списки, функции, классы, модули — **всё это объекты**, выделенные в динамической памяти (в куче).
*   **Имена (переменные):** Это просто записи в словарях (хэш-таблицах), которые называются **Пространствами имен (Namespaces)**.

#### Где хранятся объекты?
В специальной области памяти, управляемой интерпретатором. Каждый объект имеет заголовок (счетчик ссылок, тип) и тело (данные).

#### Где хранятся имена (переменные)?
Они хранятся в **словарях (dict)**:
1.  **Глобальные переменные:** В словаре модуля (`module.__dict__`).
2.  **Локальные переменные функции:** В объекте фрейма (`frame.f_locals` или оптимизированный массив).
3.  **Атрибуты объекта:** В словаре экземпляра (`instance.__dict__`).

---

### 2. Детальный разбор: Что где лежит?

Представим такой код:

```python
x = 10                  # 1. Переменная

def my_func():          # 2. Функция
    return x

class MyClass:          # 3. Класс
    val = 5

obj = MyClass()         # 4. Экземпляр
```

#### 1. Переменная `x = 10`
*   **Объект `10`:** Лежит в **Куче**. Это объект типа `int`.
    *   *Нюанс:* Числа от -5 до 256 создаются один раз при старте интерпретатора (кэш). `x` просто ссылается на этот общий объект.
*   **Имя `x`:** Лежит в **словаре глобальной области видимости** (глобальный `dict` модуля).
    *   Запись: `{'x': <ссылка на объект 10>}`.

#### 2. Функция `my_func`
Функция в Python — это полноценный объект!
*   **Объект функции:** Лежит в **Куче**. Тип: `function`.
    *   Внутри него хранятся:
        *   Ссылка на **Code Object** (скомпилированный байт-код).
        *   Ссылка на глобальный словарь (`__globals__`).
        *   Имя функции, аргументы по умолчанию и т.д.
*   **Code Object:** Тоже объект в **Куче**. Содержит сам байт-код, таблицу констант, имена переменных. Он неизменяемый.
*   **Имя `my_func`:** Лежит в **глобальном словаре** модуля.

#### 3. Класс `MyClass`
Класс — тоже объект (экземпляр метакласса `type`).
*   **Объект класса:** Лежит в **Куче**.
    *   Внутри хранит атрибуты класса (например, `val`), методы, ссылку на базовые классы.
*   **Атрибут `val`:** Хранится в словаре класса (`MyClass.__dict__`).
*   **Имя `MyClass`:** Лежит в **глобальном словаре** модуля.

#### 4. Экземпляр `obj`
*   **Объект `obj`:** Лежит в **Куче**.
    *   У него есть заголовок (ссылка на класс `MyClass`, счетчик ссылок).
    *   У него есть словарь экземпляра (`obj.__dict__`), где хранятся атрибуты объекта (если ты сделаешь `obj.a = 1`, это попадет сюда).
*   **Имя `obj`:** Лежит в **глобальном словаре** модуля.

### 3. Как устроена память внутри (CPython Memory Manager)

CPython не просит у операционной системы память (`malloc`) для каждого маленького объекта. Это было бы очень медленно. Вместо этого используется многоуровневая система.

#### Уровень 1: Raw Memory (ОС)
Python запрашивает у ОС большие куски памяти (арены), обычно по 256 КБ.

#### Уровень 2: pymalloc (Менеджер памяти Python)
Внутри этих арен Python организует свою структуру (**Objects/obmalloc.c**):
1.  **Arena (Арена):** Большой блок памяти от ОС.
2.  **Pool (Пул):** Арена делится на пулы. Каждый пул обслуживает объекты определенного размера (например, только объекты по 32 байта, или только по 64 байта).
3.  **Block (Блок):** Пул делится на блоки. Это место, где живет твой объект.

**Зачем это нужно?**
*   **Скорость:** Выделение памяти из пула быстрее, чем вызов `malloc` в ОС.
*   **Отсутствие фрагментации:** Маленькие объекты не разбрасываются по всей памяти, а лежат компактно в пулах.
*   **Возврат памяти:** Когда пул становится полностью пустым, он возвращается в арену, а когда арена пустеет — память возвращается ОС.

#### Уровень 3: Объекты
Непосредственно твои данные (`int`, `list`, `dict`). Они занимают блоки в пулах.

### 4. Управление жизненным циклом (Удаление)

Как Python понимает, что объект можно удалить?

#### 1. Счетчик ссылок (Reference Counting) — Основной механизм
У каждого объекта в заголовке есть поле `ob_refcnt`.
*   Создал объект: `refcnt = 1`.
*   Присвоил переменной: `refcnt += 1`.
*   Удалил переменную (`del x` или выход из области видимости): `refcnt -= 1`.
*   **Если `refcnt == 0`:** Память освобождается **мгновенно**. Блок возвращается в пул.

#### 2. Сборщик мусора (Garbage Collector) — Для циклов
Счетчик ссылок не справляется с циклическими ссылками:
```python
a = []
b = []
a.append(b)  # a ссылается на b
b.append(a)  # b ссылается на a
del a
del b        # Счетчики стали 0? Нет, они ссылаются друг на друга!
```
Для этого есть **GC** (модуль `gc`). Он периодически запускается и ищет такие «острова» объектов, которые ссылаются друг на друга, но на которые нет ссылок извне (из кода программы). Он разрывает циклы и очищает память.

### 5. Визуализация памяти для простого скрипта

Допустим:
```python
a = 100
b = a
```

**В памяти (Heap):**
1.  **Объект Int(100):**
    *   Адрес: `0x1000`
    *   Тип: `int`
    *   Значение: `100`
    *   `refcnt`: 2 (потому что на него ссылаются `a` и `b`)

**В памяти (Namespace Dict):**
1.  **Глобальный словарь модуля:**
    *   Ключ `"a"` -> Значение `0x1000` (указатель)
    *   Ключ `"b"` -> Значение `0x1000` (указатель)

**Что происходит при `a = 200`?**
1.  Создается (или берется из кэша) объект `Int(200)` по адресу `0x2000`.
2.  В словаре модуля ключ `"a"` обновляется на `0x2000`.
3.  Счетчик ссылок объекта `Int(100)` уменьшается на 1 (становится 1, так как `b` еще ссылается).
4.  Счетчик ссылок объекта `Int(200)` увеличивается.

### 6. Оптимизация памяти (Что стоит знать)

1.  **Interning (Интернирование):**
    *   Короткие строки и маленькие целые числа кэшируются. `a = "hello"`, `b = "hello"` -> `a is b` будет `True`. Это экономит память.
2.  **`__slots__`:**
    *   По умолчанию у каждого экземпляра класса есть свой словарь `__dict__` для атрибутов. Это занимает много памяти.
    *   Если объявить `__slots__ = ['x', 'y']`, Python выделит фиксированную память под эти атрибуты (как в struct в C), без словаря. Экономия до 40-50% памяти для миллионов объектов.
3.  **Локальные переменные функций:**
    *   Хотя логически это словарь, CPython оптимизирует доступ к локальным переменным внутри функции. Они хранятся в массиве (`fast locals`) внутри фрейма, а не в хэш-таблице, что делает доступ к ним быстрее, чем к глобальным.

### Итог

1.  **Объекты (данные):** Живут в **Куче (Heap)**, управляемой `pymalloc`.
2.  **Переменные (имена):** Живут в **Словарях (Namespaces)**, которые тоже лежат в куче.
3.  **Функции и Классы:** Это такие же объекты в куче, просто более сложные по структуре.
4.  **Стек:** Используется только для вызовов C-функций внутри самого интерпретатора и для хранения фреймов вызовов (но сами фреймы выделяются в куче).
5.  **Очистка:** Мгновенная через счетчик ссылок + периодическая для циклов через GC.

Эта модель («всё объект, всё в куче, имена — ссылки») делает Python гибким, но накладывает накладные расходы на память и скорость по сравнению с компилируемыми языками.
